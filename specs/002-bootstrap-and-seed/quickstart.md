# Quickstart Validation: Bootstrap and Seed

**Feature**: 002-bootstrap-and-seed | **Date**: 2026-08-13

How to prove this feature works end to end. Every scenario maps to a success criterion in
[spec.md](./spec.md); contract detail lives in [contracts/](./contracts/) and is referenced
rather than repeated.

**This feature is what makes the quickstart two commands.** Feature 001 left three, and one
of them needed a global tool. If any scenario below requires a step not listed under
Prerequisites, that is a defect under constitution P18.

---

## Prerequisites

- Docker (or an equivalent container runtime) running
- .NET SDK 9.0.317 or a later 9.0.x — pinned in `global.json`

Not `dotnet-ef`. Removing that prerequisite is the point of research.md R0.

---

## Scenario 1 — Cold start, two commands *(SC-001, SC-002)*

From a clean clone on a machine with no project state, with the SQL Server image already
pulled:

```powershell
pwsh ./scripts/Initialize-LocalDb.ps1
```

```powershell
dotnet run --project src/LexTime.Api
```

**Expected**: the script exits 0 in under 3 minutes having reported each step, and prints a
development token. The service then serves Swagger and a green `/health`. Step format is in
[contracts/bootstrap-cli.md](./contracts/bootstrap-cli.md).

Verify the prerequisite claim by actually removing the tool first:

```powershell
dotnet tool uninstall --global dotnet-ef
```

The script must still complete. If it fails, R0 was not implemented and P18 is not
satisfied.

## Scenario 2 — Idempotency *(SC-003)*

Run the script a second time against the completed environment.

**Expected**: exit 0; steps report "already running", "up to date", "skipped, database
already seeded"; row counts identical.

```sql
SELECT COUNT(*) FROM dbo.TimeEntries;
```

A second run that reports success indistinguishably from the first does not satisfy this —
"skipped" must be visible in the output.

---

## Scenario 3 — Reset drops the database, not the container *(FR-006)*

Note the container's start time, then:

```powershell
docker inspect -f '{{.State.StartedAt}}' lextime-sqlserver
pwsh ./scripts/Initialize-LocalDb.ps1 -Reset
docker inspect -f '{{.State.StartedAt}}' lextime-sqlserver
```

**Expected**: the database is dropped, recreated, migrated and reseeded; the two start
times are **identical**, proving the container was never restarted. No confirmation prompt
appears — the switch is the confirmation (FR-007).

---

## Scenario 4 — Partial seed is refused, not papered over *(R6)*

Interrupt the script during seeding (Ctrl+C while the load step runs), then run it again
without `-Reset`.

**Expected**: a non-zero exit stating that the database is partially seeded and that
`-Reset` is required. It must not report success, and it must not top up.

This is the failure that matters most. A partial seed looks complete, and feature 003 would
report on it faithfully and produce numbers that are wrong.

---

## Scenario 5 — Seed shape *(SC-004, SC-005, SC-007)*

The script's verification step prints all seven checks with measured values. Spot-check by
hand:

```sql
-- weekend share, expect < 10%
SELECT 100.0 * SUM(CASE WHEN DATEPART(weekday, WorkDate) IN (1, 7) THEN 1 ELSE 0 END) / COUNT(*)
FROM dbo.TimeEntries;

-- duration violations, expect exactly 0
SELECT COUNT(*) FROM dbo.TimeEntries
WHERE DurationMinutes <= 0 OR DurationMinutes % 6 <> 0 OR DurationMinutes > 1440;

-- entries after the reference date, expect exactly 0
SELECT COUNT(*) FROM dbo.TimeEntries WHERE WorkDate > '2026-08-13';

-- inactive clients that nonetheless have history, expect >= 1
SELECT COUNT(DISTINCT c.ClientId)
FROM dbo.Clients c
JOIN dbo.Matters m ON m.ClientId = c.ClientId
JOIN dbo.TimeEntries t ON t.MatterId = m.MatterId
WHERE c.IsActive = 0;
```

Entries older than 90 days are **expected**, not violations (FR-019).

## Scenario 6 — Determinism *(SC-006)*

```powershell
pwsh ./scripts/Initialize-LocalDb.ps1 -Reset
```

Capture a checksum, reset again, and compare:

```sql
SELECT CHECKSUM_AGG(BINARY_CHECKSUM(UserId, MatterId, WorkDate, DurationMinutes, IsBillable))
FROM dbo.TimeEntries;
```

**Expected**: identical values. A difference means something in the generation path reads
the clock or machine entropy, which invalidates the measurement feature 003 depends on.

The cheaper version of this assertion runs in `dotnet test` at 1/100 scale with no database
at all — that is where a regression would actually be introduced.

## Scenario 7 — Reviewer can use the printed token *(SC-008)*

Copy the token the script printed, then:

```powershell
curl -i -H "Authorization: Bearer <printed token>" http://localhost:5202/api/v1/ping
```

**Expected**: 200, with no configuration change and nothing generated by hand. Feature 001
proved the boundary accepts and rejects; this proves a reviewer can get across it.

## Scenario 8 — Failure messages name their cause *(SC-009)*

Each of these must produce a message identifying the cause before any stack trace:

```powershell
# with Docker stopped
pwsh ./scripts/Initialize-LocalDb.ps1        # expect exit 1, names the tooling

# with something already bound to 1433
pwsh ./scripts/Initialize-LocalDb.ps1        # expect exit 1, names the port
```

Judged by someone who has not read the script. "Exception of type X was thrown" is not a
compliant failure.
